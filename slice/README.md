# RecAI local thin slice

Run from this folder with Python 3.13 or 3.14. Install the pinned direct dependencies with `python -m pip install -r requirements.txt`. After setup, `python acceptance.py` runs the synthetic lifecycle and parser checks without starting a public listener or using a cloud account. `python benchmark_http.py` compares token overlap and phrase/alias retrieval through the same MCP tool. `python app.py` starts the local service on 127.0.0.1:8765. To test a separately running synthetic instance, use `python acceptance.py --base-url http://127.0.0.1:8765`.

The official MCP SDK serves stateless Streamable HTTP on `/mcp`. The two read-only tools search exact evidence and fetch a citation. The portal-side test contract uses PUT, GET and DELETE on `/documents/{id}`, where the caller supplies a random 32-character lowercase hex ID to make retrying uploads possible. Documents are owner-only within a tenant. GET, citation, overwrite and deletion require the same verified subject. Search checks owner before selecting local hits and again before returning excerpts. There is no sharing UI or group ACL yet. The test verifier uses public, synthetic fixture tokens and is suitable only for this loopback prototype. Real OAuth, protected-resource metadata, resource-bound access tokens, and real Claude sign-in remain separate gates.

The parser runs in a subprocess and has file, PDF page, DOCX expansion, extracted text and execution time limits. Up to two requests can ingest at once. Scanned PDF OCR is intentionally off and no OCR provider is wired. The local index gives direct phrase matches more weight than aliases and uses deterministic tie-breaking. It uses no embeddings and still needs a way to distinguish skill mentions from evidence of experience. The unwired cloud read adapters accept injected clients and an embedding function. They do not implement the cloud write path, durable idempotency, or resource provisioning. The local store and index are reset on restart. No AWS or paid model calls are used.

Benchmark fixtures isolate each labelled query's requested document set during test setup. This matches the original evaluation scope without adding an authorization argument to the MCP tool. The manual challenge cases exercise lookalikes, phrase meaning, aliases and misspellings. The fixture set is visible, so a separately authored blind set is still needed for an architecture decision.
