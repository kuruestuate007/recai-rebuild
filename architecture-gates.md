# RecAI architecture gates

Checked November 5, 2026. This is a primary-source review and a staging plan. No AWS resources or live endpoints were used.

## Cognito and Claude sign-in

**Verdict: works with integration work for Claude web, Desktop, mobile, and Cowork, subject to a real-client test. Native Claude Code OAuth is blocked on the documented direct Cognito configuration.** Start with the hosted Claude surfaces. Confirm with the Directory team whether a hosted-only release is acceptable. If Claude Code is required, select an authorization provider with Client ID Metadata Document (CIMD) and port-agnostic loopback support, or evaluate a standards-compliant broker before committing to Cognito.

- **Client identity.** Create a dedicated Cognito confidential app client using authorization code with S256 PKCE and the exact callback `https://claude.ai/api/mcp/auth_callback`. During the custom pilot, configure your own OAuth client in Claude. For the Directory, use Anthropic-held credentials for the exact connector URL. This avoids dynamic client registration for hosted Claude. Users still sign in and consent. The client secret authenticates the token exchange and does not replace user authorization with a machine-to-machine grant.
- **Claude Code.** Anthropic-held credentials do not cover this surface. Claude Code uses its own CIMD and either `http://localhost:<port>/callback` or `http://127.0.0.1:<port>/callback` on an ephemeral port. Cognito documents pre-registered callbacks and an HTTP localhost exception for testing. That does not establish dynamic-port matching or native CIMD support. A single registered development port is not sufficient.
- **Discovery.** On a protected request, return HTTP 401 with `WWW-Authenticate: Bearer resource_metadata="https://mcp.example.com/.well-known/oauth-protected-resource/mcp"`. Serve RFC 9728 metadata at that URL, with the exact MCP resource URL, scopes, and Cognito issuer as the first authorization server. Verify Claude follows the issuer's OIDC discovery metadata and obtains the correct authorization and token endpoints. If API Gateway's built-in authorizer intercepts the request without the required challenge, enforce authentication in the MCP handler or use a gateway arrangement that preserves the complete challenge. Metadata endpoints remain public.
- **Token validation.** Use a custom evidence-read scope and separate app clients for portal and MCP. Request Cognito resource binding for the exact HTTPS MCP URL and verify the resulting access token's signature, issuer, expiry, `token_use=access`, audience, expected client and scope. If Claude's request omits `resource`, prove a standards-compatible flow before shipping. A Cognito client ID alone is not proof of the resource audience. Verify the audience survives refresh. Derive tenant membership from trusted server-side state mapped to the validated subject. Reject ID tokens and wrong-resource or wrong-scope access tokens. Redact tokens from diagnostics.
- **Timing and refresh.** Claude documents 10 seconds for discovery, registration and token requests, and 30 seconds for refresh. It may refresh up to five minutes before expiry or after a 401. Use a proposed 15-minute staging access-token lifetime, verify Cognito refresh rotation behavior for the chosen client, and ensure invalid refresh grants return `invalid_grant`. Verify how disconnect, disabled users and revoked refresh tokens affect already-issued tokens. Test both cold and warm requests.
- **Manual test.** In a synthetic staging account, connect from real Claude web. Capture only status, safe claim checks and timing. Confirm unauthenticated challenge, correct discovery and consent, owner search success, different-tenant denial, rejected ID/wrong-audience/wrong-scope tokens, refresh, disconnect and reconnect. Repeat in Desktop or Cowork if supported at launch. Test Claude Code with independently observed loopback ports before claiming support. An MCP Inspector pass is useful and separate.

Sources: [Claude connector OAuth](https://claude.com/docs/connectors/building/authentication), [Cognito authorization and resource binding](https://docs.aws.amazon.com/cognito/latest/developerguide/authorization-endpoint.html), [Cognito token exchange and refresh](https://docs.aws.amazon.com/cognito/latest/developerguide/token-endpoint.html), [API Gateway JWT validation](https://docs.aws.amazon.com/apigateway/latest/developerguide/http-api-jwt-authorizer.html).

## Employment policy and release scope

Anthropic's Usage Policy version effective November 12, 2026 includes “screening, ranking, advancing, or rejecting candidates.” It requires that a qualified person “meaningfully review” applicable recommendations and that the affected individual “must be clearly told that AI was used.” The exclusions mention “Internal drafting, research, summarization, or analysis” and qualify that exclusion by whether it becomes the ultimate recommendation delivered. I found no general B2B exemption in the effective text or the primary announcement. The Directory Policy separately requires human oversight and “direct disclosure to consumers” for high-risk software and requires privacy, data minimization, and accurate descriptions. [Usage Policy](https://www.anthropic.com/legal/aup) · [Policy announcement](https://www.anthropic.com/news/2026-usage-policy-update) · [Directory Policy](https://support.claude.com/en/articles/13145358-anthropic-software-directory-policy)

- **Estuate internal.** Evidence gathering and summarization can support a recruiter. An internal label alone does not exempt output used to rank, advance, or reject applicants. Review the specific workflow and applicable rules before adding screening.
- **Free public synthetic demo.** Use a fixed fictional corpus with no production credentials or access. Show exact evidence and abstention. Charging nothing does not change Directory security requirements.
- **Public listing with real recruiters.** Limit the tool contract to authorized evidence and source citations, with no decision score, ordered shortlist or candidate recommendation. Search relevance within a selected document is distinct from ranking candidates. Disclose data flows and retention, test isolation, and get Estuate privacy and legal review before real data. Ask Anthropic how the Directory restriction on extraction from user-uploaded files applies if a future design reads Claude attachments. Keep initial ingestion through Estuate's portal.

## PDF parser

PyMuPDF and MuPDF are available under AGPL or commercial licensing. The precise obligations depend on the software and how it is combined and deployed. Do not infer that hosting always requires disclosure of the entire application. For the proprietary rebuild, benchmark BSD-licensed pypdf for native text, with separately gated OCR for scans. Measure page-level extraction and layout quality before choosing. If PyMuPDF is necessary, ask Estuate legal to review the exact dependency and deployment and obtain commercial terms if required. [PyMuPDF licensing](https://pymupdf.readthedocs.io/en/latest/about.html) · [pypdf repository and license](https://github.com/py-pdf/pypdf) · [pypdf OCR scope](https://pypdf.readthedocs.io/en/6.11.0/meta/scope-of-pypdf.html)
